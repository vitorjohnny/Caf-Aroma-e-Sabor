═══════════════════════════════════════════════════════════════════════════════════════
                              RELACIONAMENTOS
═══════════════════════════════════════════════════════════════════════════════════════

1️⃣  PRODUTO (1) ◀─────────▶ (N) MOVIMENTACAO
   ┌─────────────────────────────────────────────────────────────────┐
   │ • Um PRODUTO pode ter VÁRIAS MOVIMENTAÇÕEs                     │
   │ • Uma MOVIMENTAÇÃO pertence a UM único PRODUTO                  │
   │                                                                 │
   │ Mapeamento JPA:                                                 │
   │   ├─ Em Produto: @OneToMany(mappedBy = "produto")              │
   │   └─ Em Movimentacao: @ManyToOne + @JoinColumn(produto_id)     │
   │                                                                 │
   │ Cascade: DELETE (remove movimentações ao deletar produto)       │
   │ OrphanRemoval: true                                            │
   └─────────────────────────────────────────────────────────────────┘

2️⃣  USUARIO (1) ◀─────────▶ (N) MOVIMENTACAO
   ┌─────────────────────────────────────────────────────────────────┐
   │ • Um USUARIO pode fazer VÁRIAS MOVIMENTAÇÕEs                   │
   │ • Uma MOVIMENTAÇÃO é feita por UM único USUARIO                 │
   │                                                                 │
   │ Mapeamento JPA:                                                 │
   │   └─ Em Movimentacao: @ManyToOne + @JoinColumn(usuario_id)     │
   │                                                                 │
   │ Cascade: RESTRICT (não permite deletar usuário com             │
   │          movimentações - preserva auditoria)                    │
   └─────────────────────────────────────────────────────────────────┘

═══════════════════════════════════════════════════════════════════════════════════════
                              CONSTRAINTS
═══════════════════════════════════════════════════════════════════════════════════════

PRIMARY KEY (PK):
├─ usuario.id          - Identifica cada usuário
├─ produto.id          - Identifica cada produto
└─ movimentacao.id     - Identifica cada movimentação

FOREIGN KEY (FK):
├─ movimentacao.produto_id  ──→ produto.id (DELETE CASCADE)
└─ movimentacao.usuario_id  ──→ usuario.id (DELETE RESTRICT)

UNIQUE:
└─ usuario.email       - Email único por usuário

NOT NULL:
├─ usuario:    email, nome, senha
├─ produto:    nome
└─ movimentacao: tipoMovimentacao, quantidade, dataMov, produto_id, usuario_id

ÍNDICES (Para Performance):
├─ idx_usuario_email              - Busca por email
├─ idx_produto_categoria          - Busca por categoria
├─ idx_movimentacao_produto_id    - Busca por produto
├─ idx_movimentacao_usuario_id    - Busca por usuário
├─ idx_movimentacao_data_mov      - Busca por data
└─ idx_movimentacao_produto_data  - Busca composta (produto + data)

                             EXEMPLO DE USO
═══════════════════════════════════════════════════════════════════════════════════════

┌─ CENÁRIO: Registrar compra de Café Premium ─────────────────────┐
│                                                                   │
│  1. Usuário "gerente@cafe.com" entra no sistema                 │
│  2. Vai para "Controle de Estoque"                              │
│  3. Clica em "Nova Movimentação"                                │
│  4. Preenche:                                                    │
│     • Tipo: ENTRADA                                              │
│     • Produto: Café Premium                                      │
│     • Quantidade: 50 kg                                          │
│     • Observação: "Compra fornecedor XYZ"                        │
│  5. Clica "Confirmar"                                           │
│                                                                   │
│  Sistema:                                                        │
│  ├─ INSERT em MOVIMENTACAO (tipo=ENTRADA, qtd=50, ...)          │
│  ├─ UPDATE PRODUTO: estoque = 100 + 50 = 150                    │
│  └─ Sucesso! Movimentação registrada                            │
│                                                                   │
│  Depois:                                                         │
│  ├─ Gerente consulta histórico do Café Premium                 │
│  ├─ Sistema mostra todas as movimentações do produto            │
│  └─ Com data, tipo, quantidade e usuário que fez                │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
